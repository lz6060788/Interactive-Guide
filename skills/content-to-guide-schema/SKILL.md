# Content To Guide Schema

## 概述

使用这个 skill 将原始内容转换为“内容层 + 视觉层”的节点结构，服务于 Interactive Guide 的图文导览生成。

目标不是先写出一段好看的生图 prompt，而是先保住知识内容，再补适合图片生成和页面呈现的视觉表达。

优先输出这些字段：

- `summary`
- `keyPoints`
- `sourceText`
- `topicType`
- `visualIntent`
- `hotspotHints`
- 兼容旧链路时再补 `keyContent`

## 工作流

### 第 1 步：确认输入范围

- 如果用户提供单篇文档，先判断它对应一个节点还是多个节点。
- 如果用户提供文档目录，先判断目录中的每篇文档是否对应一个节点。
- 如果用户提供现有 `guide.json`，优先补全缺失字段，而不是推翻重写。

### 第 2 步：判断模式

- 默认按 `infographic-mode` 处理以下任务：
  - `新闻播报`
  - `常识介绍`
  - `内容解读`
  - `课程导览`
  - `知识图谱`
- 只有封面页、场景导览页、主题海报页等以氛围为主的页面才优先考虑 `scene-mode`。
- 如有疑义，先保内容，不要抢先写强场景化的 `keyContent`。

需要时读取这些项目文档：

- `docs/生图内容描述规范.md`
- `docs/知识输入Schema设计.md`
- 当前 guide 包中的 `guide.json`

### 第 3 步：抽取内容层

先为每个节点抽取内容层，再考虑视觉层。

#### `summary`

- 用 1-2 句说明“这页到底在讲什么”。
- 不要写成画面描述。
- 优先表达定义、结论、主题句。

#### `keyPoints`

- 提炼 3-5 个不能丢的点。
- 优先保留定义、机制、关系、对比、因果、公式、结论。
- 每条尽量独立、清晰、可验证。

#### `sourceText`

- 保留原文核心段落或等义改写。
- 不要把原文改写成文学化场景。
- 这部分是后续校验“是否偏题”的依据。

#### `topicType`

- 参考 `references/topic-types.md` 选择最接近的类型。
- 不确定时优先选更偏内容表达的类型，而不是偏风格的类型。

### 第 4 步：补视觉层

只有在内容层稳定后，再补视觉层。

#### `visualIntent`

- 说明这页适合怎样的图示表达。
- 例如：教材式对比图、时间线信息图、关系网络图、坐标示意图、模块化讲解页。
- 重点是“如何帮助理解”，不是“如何制造氛围”。

#### `hotspotHints`

- 如果当前节点通向子节点，写出适合承载热点的语义区域。
- 区域名称应接近用户能理解的模块名，而不是模糊装饰物。
- 例如：`GDP 核算方法对比区`、`总需求与总供给交汇区`。

#### `keyContent`

- 只作为兼容旧链路的补充视觉描述。
- 可以描述少量锚点、元素关系和辅助意象。
- 不能替代定义、机制、对比、公式和结论。

### 第 5 步：检查是否过度视觉化

如果出现以下情况，说明转换方向错了：

- `summary` 读起来像画面 prompt
- `keyPoints` 只剩隐喻，没有知识点
- `sourceText` 被改得看不出原文含义
- `visualIntent` 过强，强到替代知识内容
- 多个节点像同一张图的裁切变体

### 第 6 步：按任务输出

根据用户需要输出其中一种：

- 单节点字段草案
- 多节点字段草案
- 可直接写入 `guide.json` 的 JSON 片段
- 原文到节点字段的映射表
- 转换规范建议

## 输出规则

### 必须遵守

- 保留原文知识主线，不要为了画面感换成另一主题。
- 优先输出内容层字段，再输出视觉层字段。
- 对知识导览默认采用高信息密度、适合竖屏阅读的表达。
- 不要默认继承父图构图，也不要假设子节点必须像上一层的局部放大。

### 默认字段模板

```json
{
  "summary": "",
  "keyPoints": [],
  "sourceText": "",
  "topicType": "",
  "visualIntent": "",
  "hotspotHints": [],
  "keyContent": ""
}
```

### `keyContent` 的边界

- 可以有少量具象视觉提示
- 可以描述核心锚点和元素关系
- 不能把整页压缩成单一场景隐喻
- 不能覆盖 `summary` 和 `keyPoints`

## 常见请求示例

### 单节点转换

用户可能会说：

- “把这篇 Markdown 转成一个 guide 节点”
- “根据这段内容补全 `summary`、`keyPoints` 和 `visualIntent`”

优先输出单节点 JSON 片段。

### 多文档目录转换

用户可能会说：

- “把这个目录里的文档整理成一套 guide 节点草案”
- “按原始文档目录为每篇文档生成一个节点”

优先输出节点映射表，再输出 JSON 草案。

### 旧包补全

用户可能会说：

- “现有 `guide.json` 只有 `keyContent`，帮我补结构化字段”
- “把这套节点从旧生图提示词迁移到内容优先模式”

优先保留原字段，只新增和修正结构化字段。
