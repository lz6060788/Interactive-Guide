# 转换规则

## 1. 输出优先级

按以下顺序组织节点内容：

1. `summary`
2. `keyPoints`
3. `sourceText`
4. `topicType`
5. `visualIntent`
6. `hotspotHints`
7. `keyContent`

不要跳过前 3 项直接写 `keyContent`。

## 2. 字段定义

### `summary`

- 长度建议：1-2 句
- 用途：告诉系统“这页在讲什么”
- 写法：主题清晰、概念准确、不要场景化

示例：

```text
GDP 核算可以从生产法、收入法和支出法三条路径进行，三种方法理论上应得到一致结果。
```

### `keyPoints`

- 数量建议：3-5 条
- 用途：告诉系统“哪些信息不能丢”
- 写法：优先保留定义、公式、机制、关系、结论

示例：

```text
- 生产法从增加值角度核算 GDP
- 收入法从要素报酬角度核算 GDP
- 支出法从最终使用角度核算 GDP
- 三种核算方法理论上应得到同一结果
```

### `sourceText`

- 用途：保留原文依据
- 写法：引用原文核心段落，或进行等义压缩
- 禁忌：不要改写成视觉场景

### `visualIntent`

- 用途：告诉系统“怎样呈现更容易理解”
- 写法：描述图示类型、信息组织方式、页面表达重点
- 禁忌：不要把它写成文学化画面 prompt

示例：

```text
采用教材式三模块对照信息图，分别解释生产法、收入法和支出法，保留公式与代表性要素，适合竖屏阅读。
```

### `hotspotHints`

- 用途：为子节点交互入口提供语义区域
- 写法：命名清晰、接近页面模块名
- 禁忌：不要用“左边那个齿轮”“右下角装饰物”这种不稳定描述

### `keyContent`

- 用途：兼容旧链路
- 写法：仅补少量具象锚点、辅助意象、元素关系
- 禁忌：不要让它抢走内容主导权

## 3. 模式判断

### `scene-mode`

适合：

- 封面页
- 主题海报
- 强场景导览页

特点：

- 强调主体、氛围、视角
- 允许更具象、更插画化

### `infographic-mode`

适合：

- 新闻播报
- 常识介绍
- 内容解读
- 学科导览
- 机制说明

特点：

- 强调解释、关系、结构、信息密度
- 允许出现术语、公式、对比项和模块表达

默认优先使用 `infographic-mode`。

## 4. 常见错误

### 错误 1：把原文全部压成场景隐喻

```text
原文：三种 GDP 核算方法及公式
错误输出：一个巨大的经济蛋糕被三面镜子围绕
```

问题：

- 画面可能好看，但知识点已经丢失。

### 错误 2：只有视觉主题，没有信息模块

```text
错误输出：一个宏观经济驾驶舱，里面有很多精美仪表盘
```

问题：

- 用户难以从图中读出政策工具、目标和传导关系。

### 错误 3：多个节点共用一套视觉骨架

问题：

- 节点间差异只剩图标和标题变化。
- 导致知识页看起来像模板复制，而不是主题独立。

## 5. 推荐检查清单

输出前检查：

- `summary` 是否准确回答“这一页讲什么”
- `keyPoints` 是否真的不可丢
- `sourceText` 是否还能回溯原文
- `visualIntent` 是否是在帮助理解，而不是替代知识
- `keyContent` 是否退居补充位置
- 当前节点是否与兄弟节点足够区分
