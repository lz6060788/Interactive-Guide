# Interactive Guide 后端验收标准与测试方案

> 版本: 0.4.0 | 日期: 2026-05-07 | 依据: 后端详细设计方案 v0.4.0

---

## 1. 验收总则

| 原则 | 标准 |
|------|------|
| 无降级 | AI 调用失败不得写入占位数据，必须报错 |
| 类型安全 | `npx tsc --noEmit` 零错误 |
| 配置外置 | AI 配置来自 `.env`，无硬编码 |
| 错误可控 | API 错误返回 `{ error, code }` |
| 接口驱动 | 业务层通过 `Repository` 接口访问存储 |
| 路由分域 | 按领域拆分，单文件 < 200 行 |

### 2.3 导览 CRUD (services/guide-service.ts)

**验收标准**：

| 端点 | 校验 |
|------|------|
| `GET /guides` | 返回 `GuideListItem[]` |
| `GET /guides/:id` | 存在 → 200，不存在 → 404 |
| `POST /guides/import` | 有效 → 201，无效 → 400 |
| `PUT /guides/:id` | 只更新元数据，不可覆盖 nodes/edges |
| `DELETE /guides/:id` | 内存 + 磁盘删除 |
| `PUT /nodes/:nid/hotspots` | normalizedX/Y ∈ [0,1] |

```
TC-GUD-01: 列出导览        → GET /guides → 200, 含 demo 导览
TC-GUD-02: 获取详情        → GET /guides/{id} → 200, nodes[0].id === 'root'
TC-GUD-03: 导览不存在      → GET /guides/nonexistent → 404, code: "NOT_FOUND"
TC-GUD-04: 导入有效导览    → POST /guides/import → 201, 磁盘文件存在
TC-GUD-05: 导入无效导览    → POST /guides/import, 缺少 root → 400
TC-GUD-06: 更新元数据      → PUT /guides/{id} {title:"新"} → title 更新, nodes 不变
TC-GUD-07: 不可覆盖 nodes  → PUT /guides/{id} {nodes:[...]} → nodes 仍为原始值
TC-GUD-08: 更新热点-正常   → PUT .../hotspots 合法数据 → 200
TC-GUD-09: 更新热点-越界   → PUT .../hotspots normalizedX:1.5 → 400
TC-GUD-10: 删除导览        → DELETE → 200, 再 GET → 404
```

### 2.4 生成管线 (services/generate-service.ts)

**验收标准**：
- [ ] `POST /guides/:id/generate` 异步返回，含 `generateId`
- [ ] 生成结束状态 = `success` / `partial_failed` / `failed`
- [ ] 失败节点/边的 record 含 `errorMessage`，无假数据
- [ ] 产物中 `manifest.json` 通过 `validateManifest()`
- [ ] `GET /guides/:id/manifest` 返回已发布的 manifest

```
TC-GEN-01: 触发生成
  POST /guides/{id}/generate → 200, 含 generateId, status ∈ {pending,running}

TC-GEN-02: 查询状态
  10 秒后 GET /generates/{generateId} → currentStage 已推进

TC-GEN-03: 生成成功（有 API Key）
  前置: VISION/IMAGE/VIDEO_API_KEY 均配置
  期望:
    - status === 'success'
    - nodes/*/image.png > 1KB
    - edges/*/transition.mp4 > 10KB
    - manifest.json 通过 validateManifest()

TC-GEN-04: 生成失败（无 API Key）
  前置: 删除 VISION_API_KEY
  期望:
    - status === 'failed'
    - node-record.json 含 "VISION_API_KEY is not configured"
    - 无假数据

TC-GEN-05: 产物目录结构
  前置: 成功生成
  目录:
    generates/{id}/
    ├── generate.json
    ├── validation-report.json
    ├── input/guide.snapshot.json
    ├── nodes/{nodeId}/node-record.json
    ├── nodes/{nodeId}/planner.json
    ├── nodes/{nodeId}/image.png
    ├── edges/{edgeId}/edge-record.json
    ├── edges/{edgeId}/transition.json
    └── edges/{edgeId}/transition.mp4

TC-GEN-06: manifest 校验
  读取 manifest.json → validateManifest() → valid === true

TC-GEN-07: 缓存命中
  相同导览连续生成两次 → 第二次日志含 "Cache hit"

TC-GEN-08: 查询不存在的生成
  GET /generates/nonexistent → 404
```

## 3. 集成测试场景

### 场景 A: 端到端生成（成功路径）

```
前置: 三组 API Key 已配置，服务器运行

步骤:
  1. GET /guides → 确认 demo 导览存在
  2. POST /guides/{id}/generate → 获取 generateId
  3. 每 10 秒轮询 GET /generates/{generateId}，直到 status !== 'running'
  4. 确认 status === 'success'
  5. GET /guides/{id}/manifest → 返回 manifest
  6. validateManifest(manifest) → valid === true
  7. publish 目录下 .png > 1KB，.mp4 > 10KB

预期: 全流程无错误，产物完整
```

### 场景 B: 端到端生成（失败路径）

```
前置: 删除所有 *_API_KEY，重启服务器

步骤:
  1. POST /guides/{id}/generate → 获取 generateId
  2. 等待 10 秒
  3. GET /generates/{generateId} → status === 'failed'
  4. node-record 含 "is not configured"
  5. publish 目录无新产物

预期: 快速失败，错误明确，无假数据
```

### 场景 C: 导览 CRUD 生命周期

```
步骤:
  1. POST /guides/import → 导入
  2. GET /guides/{id} → 读取
  3. PUT /guides/{id} {title} → 更新
  4. PUT /guides/{id}/nodes/{nid} → 更新节点
  5. PUT /guides/{id}/nodes/{nid}/hotspots → 更新热点
  6. PUT /guides/{id}/edges/{eid} → 更新边
  7. DELETE /guides/{id} → 删除
  8. GET /guides/{id} → 404

预期: 每步正确，磁盘与内存一致
```

### 场景 D: 缓存复用

```
步骤:
  1. 第一次生成，记录耗时 T_A
  2. 第二次相同生成，记录耗时 T_B
  3. 统计 "Cache hit" 次数

预期: T_B << T_A，Cache hit 覆盖所有 AI 调用
```

## 4. 验收检查清单

### P0 — 核心功能

- [ ] 服务器启动正常，健康检查 200
- [ ] 导览 CRUD 正确
- [ ] 生成管线可执行（触发→运行→完成/失败）
- [ ] AI 失败时报错，不写入假数据
- [ ] 产物目录结构完整
- [ ] manifest.json 通过 validateManifest()
- [ ] `npx tsc --noEmit` 零错误
- [ ] Storage 层通过 Repository 接口访问

### P1 — 错误处理

- [ ] 所有错误返回 `{ error, code }`
- [ ] 无效导入返回 400
- [ ] 热点越界返回 400
- [ ] API Key 缺失报错明确
- [ ] 全局错误处理启用，无堆栈泄漏

### P2 — 缓存与性能

- [ ] 相同输入命中缓存
- [ ] 缓存文件存在于 `.cache/`
- [ ] 二次生成耗时显著低于首次

### P3 — 代码结构

- [ ] 无硬编码占位符
- [ ] 路由按领域拆分，单文件 < 200 行
- [ ] AI 代码在 `ai/` 目录
- [ ] 业务逻辑在 `services/` 目录
- [ ] 存储在 `storage/` 目录，接口与实现分离
- [ ] 优雅关闭已实现
