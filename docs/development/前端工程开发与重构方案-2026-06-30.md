## 0.1 美学方向

**主题：Cartographer's Desk · 绘图桌（现代版）**

把整个 workbench 想象成一张现代工程制图桌。这件产品的真实工作是：

- 在图片上**放置坐标精确的元素**（hotspot、focusRect）
- 处理**有序的层级结构**（upstream → midstream → downstream，是真序列）
- 长时间**精确编辑**

——它本质上就是测绘/制图工作，不是 SaaS dashboard。视觉语言匹配这份工作，但**视觉执行要现代**（不是 1990s 制图桌）。

### 视觉签名：四个功能性组件（不是装饰）

**为什么用"功能性"取代"装饰性"**：好的签名是**用过一次就离不开**的功能，不是"看到了觉得好看"的装饰。下面四个都是解决真实需求的组件，自然地构成产品的视觉签名。

| # | 签名组件 | 在哪 | 作用 | 为什么是签名 |
|---|---|---|---|---|
| 1 | **实时坐标读数** | 画布内跟随光标 | 鼠标在画布上移动时，底部状态条附近显示 `[ x: 0.482  y: 0.317 ]`（Geist Mono） | 这是"绘图桌"工作的**核心信息**——操作员随时需要知道光标的精确位置 |
| 2 | **十字坐标轴指示** | 画布右下角浮动 | 一个小 `+` + N/S/E/W 字母（ink.faint，Geist Mono 9px） | 立刻传达"这是 2D 坐标空间"——产品本质 |
| 3 | **工具栏键位标注** | 每个工具按钮 | 按钮显示图标 + 单字母快捷键（`V` / `M` / `C`） | 立刻传达"这是 power tool，支持键盘操作" |
| 4 | **富信息状态条** | 屏幕底部 24px | `rev 7 · saved 14:32 · 2 stages · 14 items · ⌥ online`（Geist Mono 11px，用 `·` 分隔） | 像 IDE 状态条——立刻传达"这是工程工具" |

**辅助视觉约定**：

- **阶段序号 `01 — 02 — 03`** 用细线连接（产业上中下游**确实是序列**，不是装饰）
- **坐标读数**一律 `[ 0.482, 0.317 ]` 形式（CAD 风格）
- **Eyebrow 标签** uppercase + 字距 0.08em（`STRUCTURE` / `INSPECTOR` / `01 · UPSTREAM`）
- **空状态插画**用 line-drawing 图标（lucide），不填充

### 配色（详细见 §4.2）

| 角色 | Token | Hex | 含义 |
|---|---|---|---|
| 纸基 | `paper` | `#F6F4EE` | 接近 off-white 的极淡暖色（不是黄米色） |
| 卡片 | `paper.raised` | `#FBFAF6` | 比 paper 略亮，接近纯白 |
| 弹窗 | `paper.overlay` | `#FFFFFF` | Modal/Popover 纯白 |
| 主文字 | `ink` | `#1A1F2C` | 深蓝黑（不是纯黑） |
| Atlas 强调色 | `brand` | `#B54318` | **氧化铁红**——赭石 |
| Catalog 强调色 | `accent` | `#5C6B3A` | **测绘橄榄** |
| 状态色 | warn / error / ok | 暖琥珀 / 深砖红 / 森林绿 | 全部降饱和 |

**为什么这套色**：

- `paper` 调到 `#F6F4EE`——比 `#F2EDE0`（黄米色）更白，但保留极淡的暖意避免冷感
- `paper.raised` `#FBFAF6` + `paper.overlay` `#FFFFFF`——形成清晰的"纸 → 卡片 → 弹窗"层叠
- `ink` `#1A1F2C` 偏蓝黑——比纯黑柔和，长时间编辑不刺眼
- `brand` `accent` 仍然用氧化铁 + 橄榄——这两个"地球色"是本设计方向的灵魂，**不能**换成常规蓝紫
- 状态色全部降饱和——避免原生刺眼色

### 字体（详细见 §4.4）

| 角色 | 字体 | 来源 | 风格 |
|---|---|---|---|
| Display / 标题 | **Instrument Serif** | @fontsource-variable/instrument-serif | 现代编辑衬线，Linear/Vercel/Stripe 同款，italic 极具个性 |
| Body / UI | **Geist Sans** | @fontsource/geist-sans | Vercel 2023 baseline，技术 sans 现代化 |
| Mono / 坐标 | **Geist Mono** | @fontsource/geist-mono | 跟 Geist Sans 配对开发 |

**为什么这三件套**：

- Instrument Serif 是 2023 年发布的现代编辑衬线，比例克制，italic 有签名感——不像 Fraunces 那么"温暖可爱"
- Geist 是 Vercel 2023 推出的新 baseline，针对屏幕渲染专门优化，跟 Next.js / 现代 SaaS 生态对齐
- Geist Sans + Geist Mono 配套开发，metric 同步——是"工程工具"语境的字体选择

### 为什么不是 AI 默认

| AI 默认长相 | 本方案 | 关键差异 |
|---|---|---|
| 暖米 + 高对比衬线 + 陶土 | 接近白 + Instrument Serif + **氧化铁红** | 纸基更白（`#F6F4EE` ≠ 陶土常见的 `#F4F1EA`）；品牌色是更深更红的氧化铁而非柔和陶土；字体是现代编辑衬线而非人本衬线 |
| 近黑 + 酸绿 | N/A（明确浅色） | — |
| 报纸 hairline + 密集栏 | 有 hairline 但语境是**工程制图**而非新闻；栏目是三栏编辑器；字体是 Geist 而非报纸典型衬线 | — |
| 现代 SaaS（Linear/Vercel 范式） | Geist + Instrument Serif + 富信息状态条 | Linear 范式通常用纯 Inter/Geist 无衬线；本方案用**编辑衬线做 display** 增加个性，跟纯 SaaS 区分 |

### 1.4 设计与可达性差距

- **零键盘交互**：V/M/C 工具切换硬编码在按钮文案里但没有 keyboard listener，方向键调整坐标、按 Ctrl+S 保存、Esc 取消——全都没有
- **零 a11y**：icon-only 按钮没有 `aria-label`、表单字段没用 `<label htmlFor>`、Inspector 错误信息没用 `aria-describedby`
- **零 i18n**：所有中文硬编码（包括按钮文案、提示语、空状态文案）
- **零 toast/notification**：保存失败 / 修订冲突只在 console.log 或页面顶部 `<small>`，用户体验差
- **零 error boundary**：单个组件抛错整个 workbench 空白
- **零 loading skeleton**：只有"加载中…"裸文本
- **零状态指示**：未保存、revision 冲突、网络断线、服务器 500——全无视觉反馈
- **主题不一致**：`theme/system.ts` 定义暗色主题，但所有页面用浅色内联样式（`#fafafa / #fff / #e5e7eb`）；theme 写了等于没写

## 2. 目标与验收标准

### 2.1 设计原则

1. **零硬编码样式**：业务组件不写 `style={{ ... }}` 块超过 1 行 token。例外：editor 画布内部的坐标计算结果（必须用 inline）。
2. **统一语义 token**：所有颜色 / 间距 / 字号 / 圆角 / 阴影必须走 `theme/system.ts` 的 token。CI 加 lint 规则禁用裸 hex。
3. **组件优先**：能复用 `<Button>` 就别写 `<button>`。自建组件封在 `components/`，跨 feature 复用。
4. **可达性默认开启**：所有交互必须有键盘支持 + aria 属性；不是"加分项"是"基础项"。
5. **错误可见**：保存失败、加载失败、网络断、revision 冲突——必须 toast + 错误状态指示；不能只在 console。
6. **编辑器表单可用**：每个 Inspector 字段必须可编辑、可保存、可验证。P0 bug 列表（§1.3）必须全部修掉。

### 2.2 量化指标

| 指标 | 目标 | 验收方式 |
|---|---|---|
| 内联 `style={{}}` 中出现裸 hex 色值的次数（业务组件） | 0 | grep gate |
| Atlas / Catalog 编辑器所有 Inspector 字段可编辑可保存 | 100% | Playwright e2e |
| Lighthouse Performance（dev build） | ≥ 85 | Chrome DevTools |
| Lighthouse Accessibility | ≥ 95 | Chrome DevTools |
| `npm run typecheck` | 0 error | CI |
| `npm run lint` | 0 error | CI |
| `npm test` 单测覆盖率（admin/） | ≥ 60% lines | c8 report |
| Playwright e2e 用例数 | ≥ 8 | tests/e2e/ |
| 键盘可达的交互比例 | ≥ 90% | 手动 + a11y linter |
| 全局加载 / 错误 / 空状态组件覆盖所有列表 / 表单页 | 100% | 视觉审查 |

### 2.3 非目标（本次明确不做）

- 运行时（`src/products/*/runtime`）UI 重构——已稳定
- 后端 API 改动
- 服务端渲染 / 国际化文案完整性（只做 zh-CN + 接口预留）
- 移动端适配（admin 是桌面工具，假设 viewport ≥ 1280px）
- 主题切换（暗 / 亮）——本次锁定暗色，符合编辑器使用习惯

## 3. 技术选型

### 3.1 UI 库：Chakra UI v3（已装，复用）

理由：theme system 已经写了一半，PnP 安装到位；Phase 7 留下的 legacy `DetailDrawer` 已经在用 Chakra，迁移成本低。

⚠️ **注意事项**：
- v3 API 跟 v2 差异大；用 `recipes` 而非 `variants`
- `bg` 和 `border` 是 reserved token 名，必须用 `base` 和 `border-default`
- 用 `createSystem(defaultConfig, { ... })` 扩展，不要替换

### 3.2 状态管理：Zustand

理由：editor 内的 selection / tool / drag state 跨多个子组件，用 React Context 会触发大面积 re-render；Zustand 的 selector 粒度更细。

```ts
// 例
const tool = useEditorStore((s) => s.tool)  // 只订阅 tool
```

只用于**客户端瞬态 UI state**（selection / tool / drag preview / panel size）。**不**用于服务端数据——见 §3.3。

### 3.3 数据层：TanStack Query v5

理由：所有 server state 走 React Query，自动处理：
- loading / error / success 三态
- 缓存（避免来回 refetch）
- optimistic update（保存时立刻看到效果）
- 失败重试 + 回滚

**删除 `src/admin/src/services/api.ts`**，迁到 `src/admin/src/features/projects/api.ts`、`features/atlas/api.ts` 等。每个 feature 暴露 typed hooks：

```ts
// 例
export function useProject(id: string) {
  return useQuery({ queryKey: ['project', id], queryFn: () => fetchProject(id) })
}
export function useUpdateAtlas(id: string) {
  const qc = useQueryClient()
  return useMutation({
    mutationFn: (patch) => updateAtlas(id, patch),
    onSuccess: () => qc.invalidateQueries({ queryKey: ['project', id] }),
  })
}
```

### 3.4 表单：React Hook Form + Zod

理由：Inspector 的字段类型多（boolean / number / string / 坐标元组）、需要 min/max 校验、需要 dirty 追踪。RHF 性能好（uncontrolled + ref），Zod schema 可以**和后端共享**（`src/domain/project-schema.ts` 已经有）。

```ts
const { register, handleSubmit, formState: { errors, isDirty } } = useForm({
  resolver: zodResolver(AtlasInspectorSchema),
})
```

### 3.5 拖拽：@dnd-kit/core

理由：当前 `AtlasCanvas` 的拖拽是裸 mousedown/mousemove 写的，**功能破损**（§1.3 P0 bug），而且没有键盘可达。dnd-kit 提供：
- Pointer + 键盘 sensor
- 拖拽预览
- 碰撞检测（用于吸附）

### 3.6 图标：lucide-react（已装）

所有 icon 一律从 `lucide-react` 取（已经装），禁止再导入其他图标库或用 emoji / SVG 内联。

### 3.7 动效：framer-motion（已装）

用于：toast 进出、modal 进出、editor 拖拽 preview、panels resize。不滥用——超过 300ms 的动效要带减弱偏好检测（`prefers-reduced-motion`）。

### 3.8 测试：Vitest + React Testing Library + Playwright

| 层 | 工具 | 范围 |
|---|---|---|
| 单元 | Vitest + RTL | hook / 纯函数 / 表单验证 |
| 集成 | Vitest + RTL + MSW | 组件 + API mock |
| E2E | Playwright | 完整操作链路：建项目 → 编辑 → 发布 → 静态预览 |

`tests/admin/atlas-editor.test.ts` 这种 smoke 保留作为类型/导入稳定性的兜底，不替代真测试。

## 4. 设计系统

> 美学方向参见 §0.1。本节定义具体 token、组件样式、画布规则——所有值必须从这里取，**禁止**在业务组件里硬编码 hex / px / 字号。

### 4.1 主题：浅色锁定

admin workbench **只用浅色主题**（与 §0.1 的"绘图桌"方向一致）。原因：

- 暖米色绘图纸基（`paper`）在长时间阅读时比纯白柔和，比冷灰温暖
- 浅色背景让 `ink`（深蓝黑）文字的对比度刚好（≈12:1，超过 WCAG AAA 的 7:1）
- 全景图作为画布内容嵌在 `paper-raised` 卡片中，**图片本身**仍然是亮色，不会出现"暗主题里嵌亮图"的违和
- 工具栏/Inspector 用 `paper-raised` 形成自然的层叠感

**禁止做主题切换**——避免维护两套 token。

#### 4.7.1 实时坐标读数

光标在画布上移动时，跟随显示规范化坐标 `[ x: 0.482  y: 0.317 ]`。

```tsx
// features/atlas-editor/components/LiveCoordinateReadout.tsx
import { useState } from 'react'
import { Box, HStack, Text } from '@chakra-ui/react'

export function LiveCoordinateReadout({ containerRef }: { containerRef: React.RefObject<HTMLElement> }): JSX.Element {
  const [coords, setCoords] = useState<{ x: number; y: number } | null>(null)

  useEffect(() => {
    const el = containerRef.current
    if (!el) return
    function onMove(e: MouseEvent) {
      const rect = el!.getBoundingClientRect()
      const x = (e.clientX - rect.left) / rect.width
      const y = (e.clientY - rect.top) / rect.height
      setCoords({ x: Math.max(0, Math.min(1, x)), y: Math.max(0, Math.min(1, y)) })
    }
    function onLeave() { setCoords(null) }
    el.addEventListener('mousemove', onMove)
    el.addEventListener('mouseleave', onLeave)
    return () => {
      el.removeEventListener('mousemove', onMove)
      el.removeEventListener('mouseleave', onLeave)
    }
  }, [containerRef])

  if (!coords) return <Box w="120px" /> // 保留占位避免 layout shift
  return (
    <HStack gap={3} fontFamily="mono" fontSize="11px" color="ink.muted" letterSpacing="0.04em">
      <Text>x: {coords.x.toFixed(3).padStart(5, '0')}</Text>
      <Text>y: {coords.y.toFixed(3).padStart(5, '0')}</Text>
    </HStack>
  )
}
```

**视觉**：`[ x: 0.482  y: 0.317 ]` 显示在画布底部状态条左侧，Geist Mono 11px，ink.muted。光标离开画布时坐标清空（保留占位避免抖动）。

所有空状态 / 错误状态 / 引导状态的插画**必须**用 `lucide-react` 的 line-drawing 风格图标，**禁止**填充图标。语义映射：

|---|---|

| 没有全景图 | `ImageOff` |
| 画布没 hotspot | `MousePointerClick` |

### 4.9 动效原则

- **微反馈**：hover 100ms，press 80ms，toast 进出 200ms
- **页面过渡**：300ms，**带** `prefers-reduced-motion` 检测
- **编辑器拖拽**：拖拽中 hotspot 跟随光标，松开后 150ms 回弹（成功）或 200ms 回到原位（失败 + toast）
- **脉冲环**：hotspot active 时外圈 1.6s 循环脉冲，`prefers-reduced-motion` 时不播放
- **禁止**花哨的入场动画 / 大块位移——保持"工程制图桌"的克制

### 6.2 统一 fetcher

`src/admin/src/lib/api-client.ts`：

```ts
export class ApiError extends Error {
  constructor(
    public status: number,
    public code: string,
    public issues?: unknown,
    message?: string,
  ) {
    super(message ?? code)
  }
}

export async function apiFetch<T>(
  path: string,
  init: RequestInit & { expectedRevision?: number } = {},
): Promise<T> {
  const { expectedRevision, headers, ...rest } = init
  const res = await fetch(`/api${path}`, {
    ...rest,
    headers: {
      'Content-Type': 'application/json',
      ...(expectedRevision !== undefined && { 'x-expected-revision': String(expectedRevision) }),
      ...headers,
    },
  })
  if (!res.ok) {
    const body = await res.json().catch(() => null)
    throw new ApiError(res.status, body?.error ?? 'UNKNOWN', body?.issues)
  }
  const json = await res.json()
  return json.data ?? json
}
```

错误统一抛 `ApiError`，上层用 `instanceof` 区分 status。

### 6.3 缓存策略

| queryKey | staleTime | gcTime | retry |
|---|---|---|---|
| `['projects']` | 30s | 5min | 1 |
| `['project', id]` | 0（编辑时总是要最新） | 10min | 1 |
| `['releases', projectId]` | 60s | 10min | 1 |

保存成功后**只 invalidate** 对应 query，不全局 refetch。

### 8.1 三栏布局

### 8.2 画布

**基础**：
- 全景图 `object-fit: cover` 填满容器

**缩放**：
- 鼠标滚轮（默认）：上下平移

- 缩放范围：0.25x ~ 4x，步进 0.1

**平移**：
- 工具为 `select` 时，按住空格 + 拖拽 = pan
- 或者按住鼠标中键拖拽

**Hotspot 操作**：
- 拖拽（@dnd-kit）：拖动时显示 ghost，松开后 PUT；保存失败回弹到原位 + toast
- 键盘：选中后方向键 ±0.01（Shift 加速到 ±0.1）
- 吸附：拖动时如距离其他 hotspot 中心 < 0.02，snap 到对齐
- 命中检测：点击空白处自动选中最近的 hotspot（命中半径 4%）

**Marker（item 标记）**：
- 只读显示，不接受拖拽
- hover 时高亮对应 StructurePanel 中的 item

## 13. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| Chakra v3 升级生态不稳定 | 部分 recipe 没文档 | 锁定 ^3.35，本项目内封装 `<Button>` 等，不直接依赖 Chakra 组件名散落 |
| React Query optimistic update 与 RHF dirty 状态错位 | 保存状态显示错误 | 集中到一个 `useDirtyProject()` hook，统一 truth source |
| dnd-kit 与现有 Canvas 测试冲突 | 测试需要重写 | 9.3 阶段同步更新测试 |
| 暗色主题用户不适 | 个案反馈 | 提供 OS prefers-color-scheme 检测但默认仍暗色 |
| 性能回退（Zustand + RHF + RQ 三层） | dev 时卡顿 | Profiler 验证，必要时降级到 Context + useReducer |

**回退策略**：每个 phase 独立分支可回退；CI gate 保证 master 始终可运行。如果某个 phase 卡住超过 2 天，回退到上一个 phase 的 master，重排计划。
