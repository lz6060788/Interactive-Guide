# 宏观经济学导览生成复盘与知识沉淀

## 1. 目的

- 记录本轮围绕 `macroeconomics-guide` 的完整调优过程。
- 复盘“为什么初版图像偏离文档内容、节点之间高度相似”。
- 沉淀后续适用于 `新闻播报`、`常识介绍`、`内容解读` 等通用场景的生成规则。
- 本文只基于本轮已确认的代码改动、数据改动和生成结果，不纳入其他未确认变更。
- 边转场视频、对象存储暴露、预览播放与状态回写的后续修复，单独记录在 `docs/边转场视频与预览链路修复-2026-05-11.md`。

## 2. 本轮目标

- 让节点图从“纯场景插画”回到“内容驱动的信息图”。
- 保证移动端竖屏画布的空间利用率，避免“横向展板塞进竖屏画布”。
- 让不同节点围绕各自文档内容独立成图，降低风格内的同质化。
- 在不推翻现有生成链路的前提下，做一轮最小可落地改造。

## 3. 初始问题

### 3.1 内容丢失

- 原始文档中包含定义、机制、关系、公式、结论等知识内容。
- 旧链路把节点核心内容压缩为单段 `keyContent`，且这段文本主要服务于生图。
- 结果是图片模型优先吸收“可画的场景”，而不是“必须保留的知识点”。

### 3.2 画面偏空

- 虽然包分辨率已经是 `390x844` 的竖屏，但 prompt 只有 `portrait` 的弱提示。
- 模型经常生成“标题 + 中间横向展板 + 上下大留白”的版式。
- 对移动端信息图来说，这种构图导致有效信息密度偏低。

### 3.3 第一层节点高度相似

- 初始生成逻辑会把父图作为参考图传递给子节点。
- `node1`、`node2`、`node3` 都继承 `root` 的视觉区域和构图惯性。
- 结果是三张图虽然主题不同，但更像同一个总览页的三个衍生局部，而不是三个独立知识页。

### 3.4 文档内容与图片偏离

- 原文讲的是经济学概念结构。
- 模型继承的是父图视觉和旧 `keyContent` 中的强视觉隐喻。
- 最终容易生成“视觉上成立，但知识上偏题”的插画页。

## 4. 本轮改动

### 4.1 节点输入从单段提示词扩展为轻量结构化内容

已在 `src/shared/types.ts` 和 `src/shared/validators.ts` 中增加并校验以下字段：

- `sourceText`
- `summary`
- `keyPoints`
- `topicType`
- `visualIntent`
- `hotspotHints`

设计原则：

- 保留 `keyContent` 兼容旧链路。
- 新字段不追求重型 CMS，只补最关键的“内容层”和“视觉层”。
- 节点可先逐步补结构化字段，不要求一次改完全部存量包。

### 4.2 Prompt 组装从“keyContent 驱动”改为“内容优先”

在 `src/server/services/generate-service.ts` 中，对节点 prompt 组装逻辑进行了以下调整：

- 优先使用 `summary` 表达页面主旨。
- 用 `keyPoints` 明确必须保留的知识点。
- 用 `sourceText` 作为原始文档参考。
- 用 `topicType` 注入场景模板。
- 用 `visualIntent` 注入页面表达方式。
- `Legacy content reference` 改为低优先级补充视觉细节，禁止覆盖主题、结构和构图。

### 4.3 竖屏构图规则显式化

在 `src/server/services/generate-service.ts` 和 `src/server/ai/vision.ts` 中增加了针对竖屏移动端画布的硬约束：

- 按从上到下阅读组织内容。
- 顶部、中部、下部都必须有有效信息区。
- 至少约 `80%` 的画布承载有效内容。
- 禁止只在中间放一块横向展板，上下大面积留白。
- 优先采用 `3-5` 个纵向堆叠或串联的信息模块。
- 标题区必须紧凑，不能吞掉过多高度。

### 4.4 完全取消父图继承

这是本轮最关键的修正。

已在 `src/server/services/generate-service.ts` 与 `src/server/ai/vision.ts` 中取消：

- 父节点图片读取
- 父节点热点区域放大
- 父图视觉身份继承
- 父图构图延续
- 父图哈希参与缓存键

结果：

- 每个节点都基于自己的结构化内容独立生成。
- 相似风格仍保留，但页面骨架和主题表达不再被父图绑死。

### 4.5 管理端支持新字段

在管理端工作台中补充了对结构化字段的编辑和展示：

- 节点可编辑 `topicType / summary / sourceText / keyPoints / visualIntent / hotspotHints`
- 工作台节点卡优先展示 `summary`
- 预览中展示 `summary` 和部分 `keyPoints`

### 4.6 宏观经济学示例包补全结构化数据

已为 `data/guides/macroeconomics-guide/current/guide.json` 中的所有节点补充：

- `sourceText`
- `summary`
- `keyPoints`
- `topicType`
- `visualIntent`
- `hotspotHints`

这些字段直接来自原始文档抽取与归纳，而不是凭空生成视觉设定。

## 5. 调整过程与验证结果

### 5.1 第一阶段：仅引入结构化内容

效果：

- `root` 的内容相关性比旧版明显提升。
- 但画面仍然偏空，且视觉上像横屏内容被塞进竖屏画布。

结论：

- 只有内容结构化还不够，必须同时约束画布利用率和移动端构图。

### 5.2 第二阶段：加入竖屏构图硬约束

效果：

- `root` 的竖屏利用率明显改善。
- 信息区分布更接近移动端长图。

结论：

- 对图像模型来说，`portrait` 只是尺寸信息，不等于“理解移动端构图”。
- 竖屏信息图需要明确写进 prompt 规则。

### 5.3 第三阶段：重生成第一层节点

第一次尝试时，`node1`、`node2`、`node3` 高度相似，并且仍有偏离文档内容的问题。

复盘后确认根因：

- 子节点继承了 `root` 的视觉入口区。
- 同风格、同模板、同竖屏约束叠加后，模型会收敛到类似的“知识卡片页”。

结论：

- 第一层节点不应继承 `root` 的图片和构图。
- 对知识导览来说，父图继承会放大视觉连续性，却削弱语义独立性。

### 5.4 第四阶段：取消父图继承后再次生成第一层节点

效果：

- `node1`、`node2`、`node3` 的差异明显增强。
- 每张图更贴近对应文档主题。
- “同一总览页的三张局部截图”问题明显缓解。

结论：

- 对抽象知识内容，独立成图优先级高于视觉连续性。

### 5.5 第五阶段：批量生成叶子节点

完成情况：

- `node4` 到 `node9` 全部生成成功。
- 过程中多次遭遇 DashScope `429` 限流。
- 采用错峰重试后，所有节点均补齐成功。

结论：

- 当前生成失败主要来自供应商限流，而不是 prompt 本身失效。
- 后续需要在构建层补自动退避和重试策略。

## 6. 本轮确认有效的规则

### 6.1 内容规则

- 先决定“讲什么”，再决定“怎么画”。
- `summary` 必须表达该页核心主题。
- `keyPoints` 必须只保留最关键、最不可丢的知识点。
- `sourceText` 应接近原文含义，而不是再做一次视觉化改写。
- `Legacy content reference` 只能作为补充视觉细节，不能主导页面。

### 6.2 构图规则

- 移动端竖屏信息图必须显式要求纵向阅读。
- 必须控制留白，不能依赖模型自行理解“长图”。
- 标题要克制，信息区要铺满中下段画布。
- 对解释型内容，优先使用图示、卡片、坐标、模块，而不是单一场景。

### 6.3 节点差异化规则

- 同一风格不等于同一版式。
- 不同节点应首先由主题结构区分，而不是由装饰元素区分。
- 第一层节点必须独立成图。
- 叶子节点也应主要依赖自身文档内容，而不是继承上层图像。

### 6.4 系统设计规则

- 结构化字段是 prompt 的上游，不是 prompt 的替代品。
- Prompt 只是最终出口，内容结构才是核心资产。
- 生成链路中任何“视觉继承”都必须谨慎，因为它会与知识独立性冲突。

## 7. 当前仍未解决的问题

### 7.1 限流问题

- DashScope 在批量重生成时多次触发 `429 Throttling.RateQuota`。
- 当前处理方式仍然是人工错峰重试。

建议：

- 在构建后台中加入指数退避重试。
- 对单节点重生接口增加更明确的限流状态反馈。

### 7.2 旧文档规范已部分过时

`docs/生图内容描述规范.md` 当前更适合“场景插画式导览”，不完全适合“内容优先的信息图导览”。

其中以下原则需要后续重写或拆分：

- “不要描述布局方式”
- “描述应该是能看到的东西，不是能读到的数据”
- “详情节点 = 一个核心主体，其他元素围绕”

这些规则对纯生图有效，但对知识导览会导致信息被压成隐喻画面。

### 7.3 `知识输入Schema设计.md` 与当前实现存在偏差

旧设计文档中曾把 `keyContent` 设想为更自由的内容块结构，但当前实现已走向“轻量结构化字段 + 兼容旧 keyContent”的方案。

后续需要同步设计文档，避免文档与实际代码不一致。

## 8. 后续建议

### 8.1 文档层

- 把 `生图内容描述规范` 拆成两套模式：
  - `scene-mode`：面向纯视觉导览
  - `infographic-mode`：面向知识导览
- 同步更新 `知识输入Schema设计.md`，反映当前已落地的轻量结构化字段。

### 8.2 生成层

- 增加按 `topicType` 派生的页面骨架模板。
- 例如：
  - `news-report`：时间线 + 事件卡 + 地图/数据区
  - `common-knowledge`：定义区 + 机制图区 + 对比区
  - `content-analysis`：观点区 + 证据区 + 关系图区

### 8.3 工程层

- 为图片生成引入自动退避重试。
- 记录更明确的单节点 prompt 版本与生效规则，方便 A/B 对比。

### 8.4 边视频与预览链路

- 边视频后续已从“仅靠视频 prompt 生成”升级为“首尾帧视觉规划 + 视频执行”两阶段链路。
- 为解决视频模型无法访问本地首尾帧的问题，节点图已补对象存储暴露能力。
- 预览热点点击与 `root` 状态回写问题已完成修复。
- 详细记录见：`docs/边转场视频与预览链路修复-2026-05-11.md`

## 9. 本轮结论

- 这次问题不是“某张图没画好”，而是旧链路天然偏向“图片驱动”。
- 通过引入轻量结构化内容、强化竖屏构图规则、彻底取消父图继承、降低旧视觉提示权重，节点图已经明显回到“内容优先”的方向。
- 对知识导览系统来说，最重要的不是保持页面像同一张母图拆开的系列图，而是让每个节点都能清楚表达自己的知识主题。
- 后续继续优化时，应坚持“内容独立性优先于视觉继承”这一原则。
- 当系统开始生成边视频时，还应坚持“先理解首尾帧关系，再生成转场”的原则，而不是让视频模型独自猜测全部中间过程。
