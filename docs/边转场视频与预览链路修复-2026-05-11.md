# 边转场视频与预览链路修复

## 1. 目的

- 记录本轮围绕 `macroeconomics-guide` 的边转场视频、预览播放链路、对象存储暴露和状态回写的完整改动。
- 说明为什么早期边视频效果不稳定，以及为什么仅靠视频 prompt 微调不足以解决低连续性边的问题。
- 为后续继续优化边转场质量保留可追踪的技术基线。

## 2. 本轮问题

### 2.1 边视频能力此前没有真正闭环

- 构建链路中存在边视频生成骨架，但单边重生成尚未完成。
- 管理端无法只针对某一条边做独立调试，导致 prompt 调整成本过高。

### 2.2 视频模型无法可靠访问首尾帧

- 早期做法是把本地节点图通过 `localhost` 暴露为 HTTP URL。
- DashScope 视频模型在实际调用中会出现 `invalid or inaccessible media_url`，说明模型侧无法稳定访问本机地址。

### 2.3 低连续性边容易退化

- 对 `node1 -> node4`、`node1 -> node5` 这类边，仅有主题相关性，不一定具有强视觉骨架连续性。
- 如果 prompt 只强调热点进入、元素桥接和 zoom-in，模型容易退化为：
  - 前半段主要停留在首帧附近做局部动画
  - 尾段突然硬切到尾帧

### 2.4 预览与状态链路存在运行时问题

- 工作台中 `root` 节点一度没有显示成功状态。
- 预览中点击热点时，边视频不会真正播放，而是直接切换节点。

## 3. 核心改动

### 3.1 补齐单边重生成链路

涉及文件：

- `src/server/services/generate-service.ts`
- `src/server/routes/generates.ts`
- `src/admin/src/services/api.ts`
- `src/admin/src/components/DetailDrawer.tsx`
- `src/admin/src/pages/WorkbenchPage.tsx`

改动内容：

- 实现 `generateService.regenerateEdge(guideId, edgeId)`。
- 新增边重生成接口 `POST /api/guides/:guideId/edges/:edgeId/regenerate`。
- 在边详情抽屉中增加：
  - 边视频预览
  - “重新生成转场”按钮
- 工作台支持从详情抽屉直接触发单边重生成。

结果：

- 可以针对单条边做 prompt 调试，不必整包重跑。

### 3.2 引入对象存储暴露首尾帧

涉及文件：

- `src/server/config.ts`
- `src/server/storage/object-storage.ts`
- `src/server/ai/media.ts`
- `src/server/ai/image.ts`
- `package.json`

改动内容：

- 新增 `OBJECT_STORAGE_*` 配置项。
- 新建 `object-storage.ts`，基于 `@aws-sdk/client-s3` 和 `@aws-sdk/s3-request-presigner` 兼容 OSS/COS。
- `media.exposeNodeImage()` 改为优先上传节点图到对象存储，并复用 `objectStorageKey/objectStorageUrl`。
- 若对象存储未配置，则回退到：
  - 供应商返回的 `modelInputUrl`
  - 或本地 `/api/media/_build/...` 暴露路径
- `NodeBuildRecord` 增加：
  - `modelInputUrl`
  - `objectStorageKey`
  - `objectStorageUrl`

结果：

- `root -> node1` 等边的视频模型可以稳定拿到首尾帧 URL。
- 当前对象存储 URL 已成为视频生成的优先素材来源。

### 3.3 从“策略判定”升级为“视觉规划”

涉及文件：

- `src/server/ai/vision.ts`
- `src/server/services/generate-service.ts`
- `src/shared/types.ts`

改动内容：

- 不再只让视觉模型返回粗粒度的 `element-bridge / fallback-navigation` 标签。
- 改为先由视觉模型输出结构化 `TransitionVisualPlan`：
  - `mode`
  - `reason`
  - `entryFocus`
  - `sourceFadePlan`
  - `targetRevealPlan`
  - `midTransitionAction`
  - `avoidances`
- `generate-service.ts` 在生成边 prompt 前，先读取首尾帧图片并调用 `planTransitionVisuals(...)`。
- `transition.json` 会落盘：
  - `strategyMode`
  - `strategyReason`
  - `visualPlan`
  - `prompt`

结果：

- 低连续性边不再只依赖视频模型现场“猜应该怎么过渡”。
- 后续可以直接比较“视觉规划结果”和“视频实际效果”之间的偏差。

### 3.4 转场 prompt 调整为知识导览语义

涉及文件：

- `src/server/services/generate-service.ts`

改动内容：

- 将边转场从“页面翻动”语义调整为“知识系统中的空间导航”。
- 明确要求：
  - 以首尾帧为硬约束
  - 入口遵循源热点真实屏幕位置
  - 主运动优先 `zoom-in / forward dive`
  - 禁止 `page-turn / paper flip / swipe / left-right pan / late cut`
- 新 prompt 会消费 `visualPlan` 中的：
  - 入口焦点
  - 源页退场计划
  - 目标页接管计划
  - 中段动作
  - 额外避免项

结果：

- `node1 -> node4` 与 `node1 -> node5` 的效果相较旧版有明显提升。
- 当前版本仍可能继续优化，但已经建立了更稳定的迭代基础。

### 3.5 修复预览播放 race condition

涉及文件：

- `src/admin/src/components/PreviewModal.tsx`

问题根因：

- 点击热点时先 `setTransitioning(true)`，又立刻读取 `videoRef`。
- 此时 `<video>` 节点还未挂载，导致代码直接 fallback 到切节点。

改动内容：

- 新增 `pendingTransition` 状态。
- 点击热点时只记录：
  - 目标节点
  - 视频 URL
- 在 `useEffect()` 中等待 `<video>` 真正挂载后再：
  - 设置 `src`
  - `load()`
  - `play()`
- 在 `onended/onerror` 中再切换到目标节点。

结果：

- 预览点击热点时，边视频可以先播放，再切换到目标节点。

### 3.6 修复 `root` 状态丢失与 JSON BOM 问题

涉及文件：

- `src/server/storage/fs-repository.ts`
- `src/server/ai/media.ts`
- `src/server/services/guide-service.ts`

问题根因：

- `root` 的 `node-record.json` 一度被写成带 BOM 的 UTF-8 JSON。
- `FsRepository.readJson()` 直接 `JSON.parse()`，解析失败后静默返回 `null`。
- `guide-service` 因此无法把 `status/imageStatus` 合并回 guide。

改动内容：

- `fs-repository.ts` 中 `readJson()` 改为在 parse 前先去掉 BOM。
- 手动修复 `root node-record.json`，恢复：
  - `status`
  - `plannerStatus`
  - `imageStatus`
  - `imagePath`
  - `objectStorageKey`
  - `objectStorageUrl`
- `media.ts` 的节点记录结构补全了状态字段定义。

结果：

- 工作台接口重新返回 `root.status = success` 与 `imageStatus = success`。
- BOM 问题不会再次导致状态静默丢失。

## 4. 管理端与运行时变化

### 4.1 工作台

- 节点状态展示更可靠，`root` 等节点不会因记录解析失败而显示成待生成。
- 边详情抽屉支持独立查看边视频与重跑边视频。

### 4.2 预览

- Manifest 加载与边视频播放链路更稳定。
- 热点点击后可以先播转场，再切换到目标节点。
- 底部信息层、图片舞台和视频覆盖层可以在同一预览模型中协同工作。

## 5. 当前结论

- 对边转场质量而言，单纯堆视频 prompt 约束是不够的。
- 更稳的方案是：
  - 首尾帧先做视觉理解
  - 产出结构化转场规划
  - 再交给视频模型执行
- 对低连续性边，后续最重要的优化点不是继续增加负向约束，而是提升 `visualPlan` 的判定质量。

## 6. 后续建议

- 优先优化 `vision.planTransitionVisuals()` 的判定标准，进一步区分：
  - 语义同构
  - 视觉骨架同构
- 对个别问题边保留单边特例能力，但不要让特例污染通用模板。
- 在边视频质检时，同时查看：
  - `transition.json` 中的 `visualPlan`
  - 实际生成视频
  - 最终用户感知是否自然
