# 独立全景 HTML 产物方案设计

## 1. 文档目标

- 定义一套独立于当前 `Interactive Guide` runtime 的新 HTML 产物方案。
- 固化该产物与现有知识包一级/二级/三级结构的映射关系。
- 明确中游/下游模板的页面布局、交互规则、编辑器能力、运行时能力与打包边界。
- 作为后续“独立编辑器、独立预览器、独立渲染核心、独立打包产物”的执行基线。

## 2. 核心结论

- 新产物不是当前项目 runtime 的一种新模式，而是一套独立 HTML 产物。
- 它与当前项目共享的核心数据只有：
  - 一级/二级/三级结构语义
  - 三级圆形标点在全景图上的定位信息
- 中游、下游共用同一套模板。
- 上游不进入本模板范围；上游是独立 HTML 节点，需要后续单独开发，并与渲染引擎通信以支持火箭、卫星等二级节点切换。
- 该方案需要新增：
  - 独立数据结构
  - 独立编辑器
  - 独立预览器
  - 独立运行时渲染核心
  - 独立打包产物

## 3. 适用范围与边界

### 3.1 本阶段纳入范围

- 中游模板
- 下游模板
- 一级 tabs
- 二级标题列表
- 三级滚动列表
- 全景图区域联动
- 三级项热点标点
- 聚焦框、遮罩、虚线连接
- 编辑器可视化配置
- 独立 HTML 预览与打包

### 3.2 本阶段不纳入范围

- 上游独立 HTML 演绎节点
- 上游与渲染引擎的通信协议具体实现
- 现有 `surface` runtime 的兼容扩展
- 现有 `SurfaceNodeDesigner` 的直接复用

## 4. 业务结构映射

### 4.1 结构语义

- 一级：上游 / 中游 / 下游
- 二级：一级下的业务模块，例如“发射服务”
- 三级：二级下的内容项，对应右侧滚动列表中的每一项

### 4.2 页面布局

- 顶部区域：一级 tabs
- 次顶部区域：当前一级下的二级标题列表
- 主视觉区域：全景背景图
- 右侧区域：三级滚动列表
- 底部区域：统一提示文案

### 4.3 固定提示文案

- 全局统一使用：`点击或滑动文字查看简介`

## 5. 交互模型

### 5.1 一级切换

- 用户点击一级 tab 后：
  - 切换到对应一级数据集
  - 刷新二级标题列表
  - 默认激活该一级下的默认二级
  - 同步切换全景图与右侧三级列表

### 5.2 二级切换

- 二级区域使用标题列表而非单标题展示。
- 用户切换二级标题后：
  - 切换当前二级数据
  - 切换默认背景区域
  - 切换右侧三级列表数据
  - 默认激活该二级下的默认三级项

### 5.3 三级激活规则

- 右侧三级列表采用“滚动激活”规则。
- 当前进入激活区域的三级项成为 `active item`。
- 点击三级项时，列表应滚动到激活位置，并进入同样的激活逻辑。
- 点击全景图上的热点标点时：
  - 右侧列表滚动到对应三级项
  - 对应三级项展开 detail
  - 背景视口、聚焦框、遮罩、连接线同步切换

### 5.4 激活后的画面变化

- 全景图移动到该三级项对应的背景区域
- 对应热点标点高亮
- 聚焦框高亮显示
- 其他区域加黑色遮罩
- 聚焦框与右侧当前项分割线左端点之间绘制虚线
- 当前三级项 detail 展开，其余项收起

### 5.5 动画要求

- 三级切换时：
  - 背景区域切换使用平移/缩放动画
  - 聚焦框切换使用位置/大小插值动画
  - 连接线随聚焦框和列表位置实时更新
- 目标不是瞬时跳变，而是“位移 + 缩放 + 高亮”的连续过渡

## 6. 数据模型设计

### 6.1 设计原则

- 不把新方案塞入现有 `surfaceConfig / surfaceLayers`
- 与现有 `PublishManifest` 共享最少公共字段
- 新方案应有独立 schema
- 背景区域与聚焦区域必须分离建模

### 6.2 建议数据结构

```ts
type PanoramaHtmlPackage = {
  id: string
  title: string
  hintText: string
  sections: PanoramaLevel1Section[]
}

type PanoramaLevel1Section = {
  id: string
  label: string
  groups: PanoramaLevel2Group[]
  defaultGroupId?: string
}

type PanoramaLevel2Group = {
  id: string
  title: string
  panoramaAsset: string
  defaultViewport: PanoramaViewport
  defaultItemId?: string
  items: PanoramaLevel3Item[]
}

type PanoramaLevel3Item = {
  id: string
  title: string
  description: string
  marker: PanoramaAnchor
  focusRect: PanoramaFocusRect
  viewportOverride?: PanoramaViewport
  connectorTarget?: PanoramaConnectorTarget
}

type PanoramaAnchor = {
  x: number
  y: number
}

type PanoramaViewport = {
  centerX: number
  centerY: number
  zoom: number
}

type PanoramaFocusRect = {
  x: number
  y: number
  width: number
  height: number
  radius?: number
}

type PanoramaConnectorTarget = {
  mode: 'divider-left'
  offsetX?: number
  offsetY?: number
}
```

### 6.3 字段规则

- `marker`
  - 三级圆形标点坐标
  - 与现有知识包中的三级热点定位信息保持一致
- `focusRect`
  - 每个三级项必须独立配置
  - 不允许继承
- `defaultViewport`
  - 二级默认背景区域
  - 三级项默认继承该区域
- `viewportOverride`
  - 仅当三级项处于不同背景区域时才显式覆盖
- `connectorTarget`
  - 当前固定连接到右侧列表分割线左端点

## 7. 页面状态机

### 7.1 核心状态

- `activeLevel1Id`
- `activeLevel2Id`
- `activeLevel3Id`
- `activeViewport`
- `activeFocusRect`
- `activeMarkerId`
- `listScrollState`

### 7.2 激活顺序

1. 初始化页面
   - 进入默认一级
   - 激活默认二级
   - 激活默认三级
2. 切换一级
   - 更新二级列表
   - 激活默认二级
   - 激活默认三级
3. 切换二级
   - 更新三级列表
   - 激活默认三级
4. 滚动三级列表
   - 激活命中项
   - 更新背景视口
   - 更新聚焦框
   - 更新热点高亮
   - 更新虚线连接
5. 点击热点
   - 滚动右侧列表到对应项
   - 触发同样的三级激活流程

### 7.3 激活判定建议

- 右侧列表采用“容器中心线命中项即激活”的规则。
- 点击某项时优先将其滚动到中心，再触发激活。

## 8. 运行时渲染要求

### 8.1 独立渲染核心职责

- 渲染顶部 tabs
- 渲染二级标题列表
- 渲染全景图
- 渲染热点标点
- 渲染右侧三级滚动列表
- 管理背景区域平移/缩放动画
- 管理聚焦框动画
- 管理遮罩开窗
- 绘制虚线连接
- 处理热点与列表的双向联动

### 8.2 技术建议

- 背景图层与聚焦层分离
- 聚焦遮罩使用单独 overlay 层
- 虚线连接使用 SVG overlay 绘制
- 所有激活态切换由统一状态机驱动，而不是多个 DOM 各自动画

### 8.3 不建议做法

- 不在当前 `PlayerHost / PlayerCore` 上继续堆叠新模板逻辑
- 不直接复用 `surface` 运行时数据结构
- 不把新模板实现成当前 runtime 的条件分支

## 9. 编辑器要求

### 9.1 编辑器目标

- 编辑器必须独立于当前 `surface` 编辑器建设。
- 支持可视化配置中游/下游全景模板
- 让运营可以直接完成背景区域、聚焦框、热点标点和右侧文案配置

### 9.2 独立性结论

- 由于该产物是独立于当前 runtime 的第二套 HTML 产物，编辑器也应独立建设。
- 独立的含义是：
  - 独立页面入口
  - 独立 schema
  - 独立画布与属性面板
  - 独立预览器
- 不独立的部分是：
  - 继续复用当前平台的知识包管理、存储、发布、鉴权、任务流和基础 UI 设施
- 推荐形态是“同一平台内的独立编辑器子系统”，而不是完全拆成另一个仓库。

### 9.3 编辑器能力

- 配置一级 tabs
- 配置二级标题列表
- 配置三级列表内容
- 配置全景背景图
- 配置二级默认背景区域
- 配置三级 `viewportOverride`
- 配置三级 `focusRect`
- 配置三级热点标点位置
- 配置右侧列表 detail
- 配置底部统一提示文案

### 9.4 可视化画布能力

- 在背景图上拖动标点
- 在背景图上框选/调整聚焦框
- 编辑默认视口区域
- 预览连接线落点
- 实时切换一级/二级/三级查看效果

### 9.5 编辑器信息架构

- 顶层对象分为：
  - 产物基本信息
  - 一级 tabs 配置
  - 二级分组配置
  - 三级项配置
  - 全景画布配置
  - 预览与发布配置
- 三级项编辑不应散落在多个无关面板中，建议以“列表 + 画布联动”的形式集中编辑：
  - 左侧或中间为结构树/列表
  - 中央为全景画布
  - 右侧为属性面板

### 9.6 编辑器页面结构建议

- 顶部工具栏
  - 保存
  - 预览
  - 发布/打包
  - 切换一级/二级上下文
- 左侧结构区
  - 一级 tabs 列表
  - 当前一级下的二级列表
  - 当前二级下的三级项列表
- 中央画布区
  - 全景图
  - 热点标点
  - 聚焦框
  - 默认视口区域
  - 连接线预览
- 右侧属性区
  - 当前一级/二级/三级项属性
  - 当前背景图和视口设置
  - 文案、连接点、提示语设置

### 9.7 与现有编辑系统的关系

- 不应继续扩展当前 `SurfaceNodeDesigner` 来承载这套产物。
- 可以复用当前 admin 的壳层能力，但应新增独立入口和独立组件树。
- 推荐在当前平台中按“产物类型”分流：
  - 当前 runtime 编辑器
  - 独立全景 HTML 编辑器
  - 后续上游独立 HTML 编辑器

## 10. 预览器要求

- 预览器独立于当前 `PreviewModal` 的 `PlayerHost` 预览体系
- 必须能实时预览：
  - 一级切换
  - 二级切换
  - 三级滚动激活
  - 背景视口移动
  - 聚焦框动画
  - 黑色遮罩
  - 虚线连接

## 11. 打包与产物要求

### 11.1 打包目标

- 新模板需要输出独立 HTML 产物
- 产物形态类比当前 runtime bundle，但入口、样式、渲染脚本独立

### 11.2 打包要求

- 支持根据产物类型选择不同 runtime 入口
- 生成新的 `index.html`
- 生成对应脚本、样式和配置数据
- 与现有知识包构建结果保持可追踪关联

### 11.3 与当前项目的关系

- 当前项目仍可作为数据来源、构建协调器和打包入口
- 但新模板应作为“独立 HTML 产物”建设，而不是继续绑定在当前运行时内核中

## 12. 上游独立 HTML 节点要求

- 上游是后续单独项目，不属于中游/下游这套模板
- 它通过 HTML 进行演绎，而不是图片 + 遮罩 + 聚焦
- 该节点需要与渲染引擎通信，以支持火箭、卫星等二级节点切换
- 需要后续单独设计：
  - 通信协议
  - 状态同步机制
  - 上游节点的独立编辑器和运行时行为

## 14. 风险与控制点

### 14.1 主要风险

- 新模板错误复用当前 `surface` 模型，导致语义混乱
- 编辑器只提供 JSON 编辑，导致运营配置成本过高
- 背景区域与聚焦区域混为一谈，后续难维护
- 右侧列表滚动激活规则不稳定，造成体验抖动

### 14.2 控制点

- 独立 schema
- 独立 runtime
- 独立预览器
- 独立编辑器
- 先做中游/下游，暂不纳入上游
