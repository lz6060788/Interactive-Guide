# 总图漫游与独立节点架构设计

## 1. 文档目标

- 为 Interactive Guide 定义新的最终态运行时与数据模型。
- 废弃旧的 `region` 局部子图节点设计，不再围绕局部框选区域构建运行时语义。
- 建立“总图自由缩放漫游 + 缩放驱动信息显隐 + 独立节点跳转”的统一方案。
- 保留真正独立的图片节点、HTML 节点、视频转场边和路由跳转能力。
- 为新的内容编辑器提供清晰、可执行、无历史包袱的数据契约。

## 2. 核心结论

新的运行时不再把“总图中的某个局部区域”视为一个独立节点，而改为以下模型：

- `surface`：可自由缩放、拖拽、镜头跳转的总图漫游节点。
- `image`：真正独立的图片节点。
- `html`：真正独立的 HTML 互动节点。

其中：

- 第一阶段只有 `root` 使用 `surface`。
- 旧 `region` 语义彻底废弃。
- 总图内的“子区域信息、标的、热点、连线卡片”全部降为 `surface` 内的内容层。
- 用户在总图中的点击热点行为，优先解释为“镜头移动到某个视角”，而不是“切换到另一个节点”。
- 只有进入真正独立的图片节点或 HTML 节点时，才发生节点切换与边转场。

## 3. 设计原则

### 3.1 强原则

- 不考虑历史兼容性，不保留旧 `region` 运行时分支。
- 不在正式代码中引入为旧包服务的兼容字段。
- 总图内镜头移动与跨节点导航必须在语义上分离。
- 所有总图标注、热点、卡片、连线，统一使用总图原图归一化坐标。
- 缩放驱动显隐规则先做简单、稳定版本：第一阶段只按缩放阈值控制。

### 3.2 第一阶段边界

- 仅 `root` 支持自由缩放漫游。
- `image` 节点继续作为独立页面节点存在。
- `html` 节点继续作为独立互动节点存在。
- 卡片最多只有一根连线。
- 连线只支持“卡片控制点 -> 图中目标点”的单终点模式。
- 总图内镜头返回按钮只负责回到该 `surface` 的初始镜头状态。

## 4. 用户体验模型

### 4.1 总图漫游

用户进入 `surface` 节点后：

- 可以自由缩放总图。
- 可以拖拽平移总图。
- 可以点击热点，让镜头平滑移动到指定区域和指定缩放级别。
- 当缩放达到某个层级后，相关信息层开始显示。

该体验更接近电子地图，而不是“进入局部子图页面”。

### 4.2 独立节点

仍然保留两类真正独立节点：

- `image`：单独展示一张图片，可继续支持 `fill / fitHeight / fitWidth` 适配策略。
- `html`：独立 HTML 页面，可保留现有 iframe 集成与 `postMessage` 交互桥。

### 4.3 跳转类型

系统中存在两类跳转：

1. 同一 `surface` 内部镜头跳转
   - 不切换节点
   - 不切换 manifest 当前 node
   - 只更新 camera

2. 跨节点跳转
   - 从 `surface` 到 `image/html`
   - 从 `image/html` 返回 `surface`
   - 仍可使用 builtin transition 或 video transition

## 5. 节点模型

### 5.1 节点类型

```ts
type NodeKind = 'surface' | 'image' | 'html'
type CoordSpace = 'surface-normalized'
```

说明：

- `surface` 用于总图漫游节点。
- `image` 用于真正独立的图片节点。
- `html` 用于真正独立的 HTML 互动节点。

### 5.2 Surface 节点

```ts
interface CameraState {
  centerX: number
  centerY: number
  zoom: number
}

interface CameraBounds {
  minZoom: number
  maxZoom: number
}

interface SurfaceConfig {
  sourceImageUrl: string
  coordSpace: CoordSpace
  initialCamera: CameraState
  bounds: CameraBounds
  gesture: {
    wheelZoom: true
    dragPan: true
    pinchZoom?: true
    inertia?: boolean
  }
}
```

说明：

- `surface` 的核心不再是局部框选，而是 `camera`。
- `initialCamera` 定义进入总图后的初始视角。
- `bounds` 用于约束缩放范围。
- 第一阶段不需要局部滑动边界，镜头只受总图边界和缩放范围约束。

### 5.3 独立图片节点

```ts
interface ImageNodeConfig {
  imageUrl: string
  imageFitMode: 'fill' | 'fitHeight' | 'fitWidth'
}
```

说明：

- `image` 节点仍然是独立节点，不参与总图内部层级显示逻辑。
- 其运行时语义与现在的普通图片节点接近，但不再和 `region` 混用。

### 5.4 HTML 节点

```ts
interface HtmlNodeConfig {
  htmlUrl: string
  htmlSource?: string
  hotspotEdgeIds?: string[]
}
```

说明：

- `html` 节点继续保留独立页面语义。
- 现有的路由跳转、宿主通信、返回按钮协议可以继续沿用。

## 6. Surface 内容层模型

### 6.1 Focus Layer

总图中的信息不再附着在独立节点上，而附着在 `surface` 的内容层上。

```ts
interface SurfaceLayerVisibilityRule {
  minZoom: number
}

interface SurfaceFocusLayer {
  id: string
  title: string
  visibility: SurfaceLayerVisibilityRule
  cameraPreset?: CameraState
  cards: SurfaceCard[]
  hotspots: SurfaceHotspot[]
}
```

说明：

- `minZoom` 是第一阶段唯一显隐条件。
- 只要当前 `camera.zoom >= minZoom`，该 layer 即可显示。
- `cameraPreset` 用于热点点击后镜头飞行落点。

### 6.2 卡片与连线

```ts
interface SurfaceCallout {
  fromDock: 'top' | 'right' | 'bottom' | 'left'
  target: {
    x: number
    y: number
  }
}

interface SurfaceCard {
  id: string
  title: string
  description?: string
  anchor: {
    x: number
    y: number
  }
  coordSpace: CoordSpace
  tags?: string[]
  stocks?: Array<{
    label: string
    valueText?: string
    action?: RuntimeAction
  }>
  callout?: SurfaceCallout
}
```

规则：

- `anchor` 表示卡片自身位置。
- `callout.target` 表示连线终点。
- `fromDock` 表示连线从卡片哪一侧引出。
- 第一阶段每张卡片最多一根线。
- 重新拖拽控制点时，旧线直接被新线覆盖。

### 6.3 Surface 热点

```ts
type SurfaceHotspotTarget =
  | {
      type: 'camera-preset'
      camera: CameraState
    }
  | {
      type: 'focus-layer'
      layerId: string
    }
  | {
      type: 'edge'
      edgeId: string
    }

interface SurfaceHotspot {
  id: string
  label: string
  anchor: {
    x: number
    y: number
  }
  coordSpace: CoordSpace
  style?: string
  target: SurfaceHotspotTarget
}
```

说明：

- `camera-preset`：点击后只在当前总图内移动镜头。
- `focus-layer`：点击后读取该 layer 的 `cameraPreset` 并移动镜头。
- `edge`：点击后触发跨节点导航。

这样可以把“总图内跳转”和“跨节点跳转”统一纳入一个热点模型，但运行时执行逻辑分离。

## 7. 动作协议

卡片中的标的按钮、标签动作继续由宿主层统一执行。

```ts
type RuntimeAction =
  | { type: 'navigate-edge'; edgeId: string }
  | { type: 'open-route'; route: string; openMode?: 'current-tab' | 'new-tab' }
  | { type: 'open-url'; url: string; target?: '_self' | '_blank' }
```

说明：

- 原先“点击标的跳转路由”的需求直接保留。
- `surface` 卡片与 `html` 节点中的动作协议可以统一。

## 8. 边与转场模型

### 8.1 总原则

- `surface` 内部跳转优先使用 camera tween，而不是边。
- 只有跨节点切换时，才由边承担转场职责。

### 8.2 边的职责

边只处理以下场景：

- `surface -> image`
- `surface -> html`
- `image -> surface`
- `image -> html`
- `html -> surface`
- `html -> image`

### 8.3 转场类型

保留：

- `builtin`
- `video`
- `none`

但移除：

- `target-region-auto`
- 所有专门服务 `region` 的视窗求解规则

### 8.4 镜头移动

同一 `surface` 内的镜头移动不再使用 edge 配置，而使用：

```ts
interface CameraTweenConfig {
  duration: number
  easing: 'ease-in-out' | 'ease-in' | 'ease-out' | 'linear'
}
```

可作为 `surface` 默认配置，也可允许热点局部覆盖。

## 9. 运行时架构

### 9.1 总体结构

运行时建议收敛为三类渲染入口：

- `renderSurfaceNode()`
- `renderImageNode()`
- `renderHtmlNode()`

### 9.2 PlayerCore

新增核心职责：

- 维护当前节点 ID
- 维护当前 surface camera
- 区分“surface 内镜头移动”和“跨节点导航”
- 维护 surface 返回状态

建议新增接口：

```ts
getNodeKind(nodeId)
isSurfaceNode(nodeId)
getCurrentCamera()
setCurrentCamera(camera)
navigateSurfaceCamera(targetCamera)
resetSurfaceCamera()
```

### 9.3 PlayerHost

`renderSurfaceNode()` 负责：

- 渲染总图原图
- 应用 camera transform
- 接管 wheel / drag / pinch 交互
- 根据 zoom 计算可见 layer
- 渲染 cards / callout / hotspots
- 在镜头更新后同步所有 overlay 的位置

`renderImageNode()` 负责：

- 渲染独立图片节点
- 继续支持 `fill / fitHeight / fitWidth`

`renderHtmlNode()` 负责：

- 渲染 iframe
- 复用既有 bridge 和预加载机制

### 9.4 建议新增模块

建议引入以下独立模块：

- `surface-camera-controller.ts`
- `surface-layer-visibility.ts`
- `surface-overlay-renderer.ts`
- `surface-coordinate.ts`
- `surface-history.ts`

职责拆分：

- `surface-camera-controller.ts`
  - 处理 camera 与 DOM transform
  - 处理 wheel / drag / pinch / tween

- `surface-layer-visibility.ts`
  - 根据当前 zoom 解算哪些 layer 可见

- `surface-overlay-renderer.ts`
  - 渲染卡片、连线、热点

- `surface-coordinate.ts`
  - 统一坐标换算

- `surface-history.ts`
  - 管理总图内“返回到初始视角”的逻辑

## 10. 返回逻辑

### 10.1 Surface 内部

当用户在 `surface` 内通过热点或手势改变镜头后：

- 可以显示返回按钮
- 该按钮的行为不是返回上一个局部节点
- 而是将镜头平滑恢复到 `surface.initialCamera`

### 10.2 跨节点

跨节点时仍然维持正常的导航历史：

- 从 `surface` 进入独立 `image` 或 `html`
- 点击返回时，回到进入前的节点

因此运行时需要把：

- `surface camera history`
- `node navigation history`

区分为两套逻辑，而不是继续混在同一条 `region` 历史栈里。

## 11. 编辑器设计

### 11.1 总体方向

废弃 `RegionNodeDesigner` 的设计中心，改为新的 `SurfaceEditor`。

### 11.2 SurfaceEditor 的核心能力

第一阶段应支持：

1. 浏览总图
2. 滚轮缩放
3. 拖拽平移
4. 保存当前镜头为热点目标视角
5. 创建热点
6. 创建卡片
7. 拖动卡片位置
8. 从卡片四周控制点拖出一根连线到图中目标点
9. 编辑卡片标题、描述、tags、stocks 和动作
10. 配置热点目标类型是：
    - 仅镜头跳转
    - 跳转到某个 layer
    - 触发跨节点 edge

### 11.3 编辑器中的连线交互

建议交互：

- 卡片四周提供固定控制点：上、右、下、左。
- 用户拖拽某个控制点到总图上的目标位置后，生成一根线。
- 一张卡片只允许存在一根线。
- 再次拖拽任意控制点时，替换原线。

### 11.4 独立节点编辑

除 `SurfaceEditor` 外，仍保留：

- `ImageNodeEditor`
  - 编辑标题、图片、适配方式、出边

- `HtmlNodeEditor`
  - 编辑 HTML 文件、路由桥接、出边

因此编辑器的职责分层建议变为：

- `SurfaceEditor`：编辑总图内语义层
- `ImageNodeEditor`：编辑独立图片节点
- `HtmlNodeEditor`：编辑独立 HTML 节点

## 12. 构建与发布

### 12.1 发布产物

发布时 manifest 需要能直接表达：

- 哪个节点是 `surface`
- 哪些节点是 `image`
- 哪些节点是 `html`
- `surface` 的 camera 配置
- `surface` 的 layer / card / callout / hotspot 配置

### 12.2 不再生成 region 相关产物

以下产物不再属于正式设计：

- region viewport
- panRange
- region overlay
- target-region-auto
- region 初始窗口求解

## 13. 实施建议

建议按以下顺序实施：

1. 重写共享类型，建立 `surface / image / html` 三类节点模型
2. 删除 `region` 运行时与相关视窗求解逻辑
3. 在 runtime 中实现 root `surface` 漫游
4. 实现缩放驱动的 layer 显隐
5. 实现卡片、单根连线、surface 热点
6. 复用并保留独立图片节点与 HTML 节点能力
7. 建设新的 `SurfaceEditor`
8. 用新模型重建验证数据

## 14. 当前最终方向

当前推荐的最终架构是：

- 用 `surface` 承接总图漫游
- 用 `focus layer` 承接总图中的分区信息
- 用 `camera` 取代 `region viewport`
- 用缩放阈值驱动信息显隐
- 用 `image` 和 `html` 保留真正独立的节点
- 用边和视频转场只处理跨节点切换

这套设计的目标不是兼容旧方案，而是直接建立新的主干模型，使运行时语义、编辑器操作方式和内容生产流程重新对齐。
